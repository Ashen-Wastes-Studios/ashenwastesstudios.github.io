Architecture

Ashen AI pairs two model pipelines with two user interfaces that share the same backend behaviors.

Model Pipelines

Base Qwen3.5-0.8B (HuggingFace, upstream hidden_size=1024) From-scratch Qwen-style decoder-only
Current Width hidden_size 1448 — upscaled once by √2, depth unchanged n_embd 512 (pre-upscale checkpoint)

Attention Hybrid — 3 linear_attention + 1 full_attention per 4-layer group Causal multi-head self-attention
FFN SwiGLU dense — or MoE (4 experts, Top-2) SwiGLU MoE — 4 experts, Top-2 gating
Tokenizer Qwen BPE (AutoTokenizer, 248,320 vocab) GPT-2 BPE via tiktoken (50,257 vocab)
Fine-tune LoRA (bf16, r=32) → merged HF ckpt Full / width-upscaled weights (.pk1)
Max Context 8,192 tokens (context_length) 8,192 tokens (block_size)

Hardware Optimization (RTX 3060 Ti, 8.59 GB VRAM)

  • Qwen inference defaults to 4-bit (bitsandbytes) to fit the 2.13 GB bf16 weights in ~0.6 GB
  • kv_cap / gen_cap clamp KV-cache and generation length to prevent OOM
  • Gradient checkpointing at long context + periodic empty_cache() + gc.collect()
  • Width-upscaling: the default checkpoint is widened by √2 with Net2Net copy-init (1024 → 1448), depth unchanged, so capacity grows with a minimal loss spike
  • MoE training freezes the base model + all experts and trains only routers + LoRA on expert projections (~5 GB)
The hidden_size of the fine-tuned checkpoint (1448) is not a multiple of 64, so bitsandbytes' 4-bit matmul falls back to a slower kernel and prints a harmless UserWarning. The dimension is fixed by the saved weights and cannot be changed without retraining — do not edit config.json to "fix" the warning, it crashes loading with a shape mismatch.

Typical Workflow

  1. Train/fine-tune — qwen_finetune.py produces the default ashen_gpt_model/
  2. Chat — launch the CLI or web interface; the model loads the saved checkpoint automatically (current_model in settings.json selects which)
  3. Agent mode — ask the model to inspect files, run commands, or explore your workspace
  4. Evaluate & improve — use Swarm / Council for hard prompts and the Self-Improve dashboard for feedback tuning

Training & Fine-Tuning

Two training entry points, one per model pipeline. Both tee output to training_logs.txt (ANSI-stripped) in addition to the terminal.

qwen_finetune.py — LoRA Fine-Tune (Default)

Fine-tunes Qwen3.5-0.8B with LoRA in bf16, emits a merged HuggingFace checkpoint at ashen_gpt_model/ plus a small class_head.pt for intent routing. LoRA on a 0.75B bf16 base (~1.5 GB) + adapters + AdamW state + activations fits comfortably in 8.59 GB; a full bf16 fine-tune would not.

MoE (Mixture-of-Experts)

Replace each layer's dense MLP with sparse MoE before LoRA. Only top-k experts activate per token — parameter count grows without proportional compute increase. On checkpoint save, MoE layers collapse to dense MLPs automatically.

Variable Default Meaning
QWEN_MOE 0 Enable MoE
QWEN_MOE_EXPERTS 4 Experts per layer
QWEN_MOE_TOPK 2 Experts activated per token
QWEN_MOE_AUX 0.01 Load-balancing aux-loss weight
QWEN_MOE_EXPERT_DIV 1 Expert intermediate-size divisor (1 = full, 2 = half)
QWEN_MOE_MERGE_ON_SAVE 1 Collapse MoE → dense MLP on export

ashen_gpt_trainer.py — Legacy Pre-Training

Trains the from-scratch Qwen-style MoE (SwiGLU, 4 experts, Top-2 gating) on the book/code corpus and saves ashen_gpt_model.pk1. Architecture: n_embd=512, n_layer=8, n_head=8, block_size=8192. Data is streamed from train_split.txt / code_train_split.txt / val_split.txt via memory-mapped windows (O(1) RAM regardless of dataset size). A VRAM-aware plan picks batch / context / accumulation from live free VRAM, and an auxiliary intent-classification head is trained on a small balanced batch every step.

The checkpoint ships at n_embd=512 (127M params). On the next run the trainer detects it and width-upscales by √2 (512 → 720) with Net2Net copy-init, depth unchanged, so a resumed run grows capacity without retraining from scratch.

Chatbot Interfaces

Both front-ends share the same streaming engine (AshenAIAgenticEngine.solve_with_agent_stream) and the same event schema, so reasoning, tool calls, citations, and CoT display are identical across CLI and web.

Cybernetic theme & pinned input box

  • Cybernetic theme — neon / box-drawing terminal UI, toggle with /cyber on|off or set ASHEN_CYBER=1. Defaults on when stdout is a TTY.
  • Pinned input box — the prompt box is anchored to the bottom via an ANSI scroll region (DECSTBM); the model's CoT and answer stream above it and the box clears in place each turn. Falls back to a plain prompt when not a TTY, when the theme is off, or on a short terminal.

Chain-of-thought display

The CLI renders streamed chain-of-thought with the same UX as the web UI — CoT in gray, the final answer in white, amber dot + model label, Sources when the model cites, and [TOOL: name(args)] for agent tool calls.

Web Chatbot (web_chatbot.py)

Browser UI via stdlib http.server at http://localhost:5000. Cyberpunk theme, Model Hub, live CoT streaming, swarm/council dashboard, self-improvement panel.

Features

  • Model Hub — browse local .pk1 / .gguf checkpoints and Qwen HuggingFace dirs (auto-tagged QWEN), upload weights, swap models live
  • Quick-action chips — File Glob, Grep, Git Status, Run Tests, Web Search, Browse URL, Deep Research, Run Benchmark
  • Live CoT streaming — NDJSON start → thought_delta → thought_done → response_delta → done, with tool_start / tool_result mid-loop
  • Persona switcher — Ashen AI Agent, Code Architect, Cyber Companion
  • Adjustable settings — temperature, top-k, top-p, max tokens, context length, GPU layers, repeat penalty, precision, CPU offload, low-end GPU mode, speculative decoding, CoT-as-Answer
  • Sessions & workspace — session list / new / load / delete / rename, workspace browser, workspace context injection, settings.json auto-created on first run

Swarm & Council

Swarm

Spawns 2–6 isolated engine copies with different roles (Researcher, Coder, Critic, Planner, Executor, Analyst) in parallel, divide, or debate modes. A Synthesizer merges all drafts into one answer. The live variant streams each agent's CoT.

Council

Drafts → critics vote and suggest → tallied winner → finalizer refines. Critics are Accuracy, Clarity, Completeness, Safety, and Efficiency. Useful for hard prompts that benefit from multi-perspective critique.

LLM Benchmark Suite

Built-in evaluation across 5 categories — Knowledge, Code Generation, Math Reasoning, Language Understanding, and Ethics & Safety — with 12 standardized questions and a letter grade. Trigger via [TOOL: run_benchmark()] or the web Run Benchmark button (~30–60 s).

Safety & Alignment

  • Behavior baked into training data — all "how to respond" lives in SFT/DPO data, never in the prompt
  • Runtime refusal filter — a 33-pattern pre-check refuses illegal/harmful requests with an apology + lawful alternative, across every backend
  • Code safety — evaluates code before providing it; refuses malware, theft, surveillance, extortion, sabotage, DoS, counterfeit, and spam
  • Intent classification head — auxiliary 5-way head classifies inputs as spam / not_spam / question / answer / request
  • Shell blocklist — destructive commands (rm -rf /, mkfs, format, shutdown, fork bombs) are blocked even when shell tools are enabled
  • File/shell gates — allow_file_tools / allow_shell_tools settings plus ASHEN_ALLOW_FILES=0 / ASHEN_ALLOW_SHELL=0 env kill-switches
  • Prompt-injection posture — retrieved web text is treated as untrusted reference data, not instructions
