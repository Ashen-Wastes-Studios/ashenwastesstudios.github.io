Architecture

Ashen AI pairs two model pipelines with two user interfaces that share the same backend behaviors.

Model Pipelines

Component Qwen Fine-tune (default) Legacy Custom
Base Qwen3.5-0.8B (HuggingFace) From-scratch Qwen-style decoder-only
Norm Qwen RMSNorm + QK-Norm RMSNorm (no mean-centering)
Position Qwen RotaryEmbedding (RoPE) RotaryEmbedding with Dynamic NTK scaling
Attention scaled_dot_product_attention (causal) same
FFN SwiGLU dense — or MoE (4 experts, Top-2) SwiGLU MoE — 4 experts, Top-2 gating
Tokenizer Qwen BPE (AutoTokenizer) GPT-2 BPE via tiktoken (50,257 vocab)
Fine-tune LoRA (bf16, r=32) → merged HF ckpt Full / width-upscaled weights (.pk1)
Max Context 8,192 tokens 8,192 tokens

Hardware Optimization (RTX 3060 Ti, 8.59 GB VRAM)

  • Qwen inference defaults to 4-bit (bitsandbytes) to fit weights in ~0.6 GB
  • kv_cap / gen_cap clamp KV-cache and generation length to prevent OOM
  • Gradient checkpointing at long context + periodic empty_cache() + gc.collect()
  • Width-upscaling: checkpoints are widened by √2 on re-run (512 → 720) with Net2Net copy-init

Installation

Bundled CUDA Venv (Recommended on Windows)

cd C:\dev\Ashen AI Base
call cuda\Scripts\activate.bat
python -m pip install --upgrade pip
python -m pip install huggingface-hub safetensors accelerate gguf llama-cpp-python numpy pyyaml

Manual Install (Clean Venv)

python -m venv venv --system-site-packages
call venv\Scripts\activate.bat
python -m pip install torch torchvision --index-url https://download.pytorch.org/whl/cu121

Typical Workflow

  1. Train/fine-tune — qwen_finetune.py produces the default ashen_gpt_model/
  2. Chat — launch the CLI or web interface; model loads the saved checkpoint
  3. Agent mode — ask the model to inspect files, run commands, or explore your workspace
  4. Evaluate & improve — use Swarm / Council for hard prompts and Self-Improve dashboard for feedback tuning

Training & Fine-Tuning

qwen_finetune.py — LoRA Fine-Tune (Default)

Fine-tunes Qwen3.5-0.8B with LoRA in bf16, emits a merged HuggingFace checkpoint at ashen_gpt_model/ plus a small class_head.pt for intent routing.

Key Environment Variables

Variable Default Purpose
QWEN_ITERS 200 Training iterations
QWEN_EVAL_EVERY 20 Eval/stream cadence
QWEN_LORA_R 32 LoRA rank
QWEN_KV_CAP / QWEN_GEN_CAP 2048 / 512 Inference VRAM caps
QWEN_GGUF 1 Enable GGUF export
QWEN_MOE 0 Enable Mixture-of-Experts training

MoE (Mixture-of-Experts)

Replace each layer's dense MLP with sparse MoE before LoRA. Only top-k experts activate per token — parameter count grows without proportional compute increase. On checkpoint save, MoE layers collapse to dense MLPs automatically.

ashen_gpt_trainer.py — Legacy Pre-Training

Trains from-scratch Qwen-style MoE on the book/code corpus. Architecture: n_embd=512, n_layer=8, n_head=8, block_size=8192. Progressive context (512 → 2K → 8K), gradient checkpointing, memory-mapped data streaming.

Swarm & Council

Swarm

Spawns 2–6 isolated engine copies with different roles (Researcher, Coder, Critic, Planner, Executor, Analyst) in parallel, divide, or debate modes. A Synthesizer merges all drafts into one answer.

Council

Drafts → critics vote and suggest → tallied winner → finalizer refines. Useful for hard prompts that benefit from multi-perspective critique.

LLM Benchmark Suite

Built-in evaluation across 5 categories: Knowledge, Code Generation, Math Reasoning, Language Understanding, and Ethics & Safety. 12 standardized questions with letter grades. Trigger via [TOOL: run_benchmark()].

Safety & Alignment

  • Behavior baked into training data — all "how to respond" lives in SFT/DPO data, never in the prompt
  • Runtime refusal filter — illegal/harmful requests are refused with apology + lawful alternative
  • Code safety — evaluates code before providing it; refuses malware, theft, surveillance, etc.
  • Intent classification head — auxiliary head classifies inputs as spam / not_spam / question / answer / request
  • Shell blocklist — destructive commands (rm -rf /, format, shutdown) are blocked even when shell tools are enabled
