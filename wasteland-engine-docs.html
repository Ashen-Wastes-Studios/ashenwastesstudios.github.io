Overview

Wasteland Engine is a 2D/3D game engine built from scratch in C++17. It uses a layered architecture with an Application core, a Scene/Entity system built on EnTT, four interchangeable rendering backends (OpenGL, D3D11, D3D12, and Vulkan — the last three through NVRHI), the Nova GPU path tracer, Python scripting via pybind11, and a full editor (DemonCore-Editor).

Runtime API Switching

The rendering backend is chosen at runtime, not at build time. Window::SwitchRendererAPI() tears down the current device and swap chain, rebuilds every GPU resource through RecreateResources(), and brings up the target backend — no relink, no separate executable. The Nova path tracer attaches to whichever Direct3D backend is active (D3D11 or D3D12); Vulkan and OpenGL run the raster path.

Device loss is detected and recovered: NVRHIContext tracks a lost-device flag and can recreate the device, swap chain, and all ImGui-side descriptor resources in place.

Core Systems

Application (Wasteland/Core/Application.h)

The Application class is the entry point for all Wasteland programs. It owns the window, runs the main loop, and manages the layer stack. Each executable supplies a CreateApplication() factory that the shared EntryPoint.h calls.

class Application {
public:
    Application(const std::string& name = "Wasteland App");
    void Run();
    void OnEvent(Event &e);
    void PushLayer(Layer *layer);
    void PushOverlay(Layer *layer);
    void Close();

    inline static Application &Get() { return *s_Instance; }
    static bool IsInitialized() { return s_Instance != nullptr; }
};

The main loop calls OnUpdate() on every layer, renders ImGui overlays, and swaps the window buffer. IsInitialized() exists so that code reachable from Python can null-check the singleton before dereferencing it — calling Get() before the app exists is a fault, not a null.

Entry Point (Wasteland/Core/EntryPoint.h)

Every executable includes this header last. It resolves the asset working directory by walking up from the executable until it finds an assets/ directory, initializes the logger, then brackets three profiled sessions around app construction, Run(), and teardown. This is why the editor and Sandbox can be launched from any working directory.

Layer (Wasteland/Core/Layer.h)

Layers are the primary unit of engine functionality. Both the editor and game systems are implemented as layers.

class Layer {
public:
    Layer(const std::string &name = "Layer");
    virtual void OnAttach() {}
    virtual void OnDetach() {}
    virtual void OnUpdate(Timestep ts) {}
    virtual void OnImGuiRender() {}
    virtual void OnEvent(Event &event) {}
    inline const std::string &GetName() const { return m_DebugName; }
};

LayerStack maintains two lists — regular layers and overlays — so ImGui always renders above gameplay regardless of push order.

Platform Layer (Wasteland/src/Platform/)

Windowing and input are split per-OS under Platform/ — Windows/, Linux/, and Mac/ each provide a window class, an input class, and platform utils. The rendering backends live beside them in Platform/OpenGL/ and Platform/NVRHI/. This is the largest single area of the engine at ~8,400 lines.

Timestep (Wasteland/Core/Timestep.h)

A float wrapper representing seconds since the last frame. Provides GetSeconds() and GetMilliseconds().

Window (Wasteland/Core/Window.h)

Abstracts platform-specific window creation. Beyond the usual size/vsync/native-handle access it owns two graphics-specific responsibilities:

  • SwitchRendererAPI(RendererAPI::API) — hot-swaps the backend at runtime
  • GetCurrentContext() — returns the GraphicsContext owning the device and command list

GraphicsContext (Wasteland/Renderer/GraphicsContext.h)

The minimal surface a window must satisfy for rendering: Init(), SwapBuffers(), and an optional BeginFrame(). OpenGLContext and NVRHIContext implement it.

RendererAPI (Wasteland/Renderer/RendererAPI.h)

The abstract backend interface — Init, SetViewport, SetClearColor, Clear, DrawIndexed, DrawLines, SetLineWidth, and SetActiveTextures. The active API enum is a static on the class, and RenderCommand is a static inline facade over the current instance, so all render paths dispatch through one call site.

Events (Wasteland/Events/)

Blocking event system dispatched immediately through EventDispatcher. Events carry a bitmask category (Application, Input, Keyboard, Mouse, MouseButton) so a handler can filter by IsInCategory():

  • WindowCloseEvent, WindowResizeEvent
  • KeyPressedEvent (with repeat count), KeyReleasedEvent, KeyTypedEvent
  • MouseButtonPressed/ReleasedEvent, MouseMovedEvent, MouseScrolledEvent

Input (Wasteland/Core/Input.h)

Static facade over the per-platform input implementation, exposing IsKeyPressed, IsMouseButtonPressed, and GetMousePosition. GetMouseDelta() is deliberately stateful — it diffs against the previous sample and consumes the cache, so a second call within the same frame correctly returns (0, 0). Call it exactly once per frame.

UUID (Wasteland/Core/UUID.h)

64-bit entity identifier with spdlog formatter support. Every entity carries one, which is what scene serialization and the editor's AI entity tools key on.

Log (Wasteland/Core/Log.h)

Static logger using spdlog. WL_CORE_INFO(), WL_CORE_ERROR(), and the WL_ERROR() family. WL_ASSERT / WL_CORE_ASSERT are compiled out entirely outside Debug builds.

Math (Wasteland/Math/Math.h)

Small math helpers layered over GLM — notably DecomposeTransform(), which pulls translation, rotation, and scale back out of a composed matrix.

Scene System

Scene (Wasteland/Scene/Scene.h)

The Scene owns an entt::registry and manages entity lifetime. It handles three update paths:

  • OnUpdateEditor() — Editor preview with EditorCamera
  • OnUpdateRuntime() — Play mode
  • OnUpdateSimulation() — Physics-only simulation

Each is bracketed by a matching start/stop pair (OnRuntimeStart/Stop, OnSimulationStart/Stop) that spins up and tears down the relevant systems.

The scene also owns the per-frame gather that feeds the renderer — RenderScene() walks the registry and dispatches to SubmitVolumetricVolumes(), SubmitSceneLights(), UpdateWater(), and SubmitWaterSurfaces(). Water gameplay queries (GetWaterHeightAt, IsUnderwater) live here and are forwarded through Entity, so C++ and Python see the same surface.

Entity (Wasteland/Scene/Entity.h)

An Entity is a lightweight handle wrapping an entt::entity and its parent Scene. It provides a templated component API:

Entity entity = scene.CreateEntity("Player");
entity.AddComponent<TransformComponent>();
auto &transform = entity.GetComponent<TransformComponent>();
bool has = entity.HasComponent<SpriteRendererComponent>();
auto *maybe = entity.TryGetComponent<MaterialComponent>();  // null instead of asserting

GetComponent asserts on a missing component; TryGetComponent returns a pointer. This distinction matters in scripting, where a missing component is an expected case rather than a bug.

TransformComponent

Translation, Rotation, and Scale as glm::vec3, with a cached matrix that is rebuilt only when one of the three changes. GetTransform() returns the cached TRS matrix; SetTransform() decomposes an incoming matrix back into TRS.

Rotation is stored in radians. The editor converts to and from degrees at the UI boundary, but the value that reaches glm::quat() — and the value a script must write — is radians. Writing degrees produces a camera that faces somewhere other than where the script aimed it.

Scene Serialization (Wasteland/Scene/SceneSerializer.h)

YAML-backed, producing .wastescene files. The serializer exposes both a static and a runtime variant of each direction — Serialize/Deserialize for editor scenes and SerializeRuntime/DeserializeRuntime for cooked output. Scene::Copy() duplicates a scene for play mode.

Rendering

Two 3D Paths

Renderer3D runs one of two paths, selected by whether ray tracing is enabled and which backend is active:

  • Raster (Basic) — the classic forward path (Renderer3D_Basic). Runs on every backend including Vulkan and OpenGL. Unshadowed, analytic lights only.
  • Nova — the GPU path tracer. Native compute on D3D11 and D3D12.

Both consume the same per-frame submissions from the scene, so an entity looks the same either way apart from shadows, reflections, and indirect light.

Renderer3D (Wasteland/Renderer/Renderer3D.h)

The static 3D entry point. Quality is set through QualityPreset:

enum class QualityPreset : int { Low = 0, Medium = 1, High = 2, Ultra = 3 };

The preset scales volumetric step counts and turns on a fast-path branch for fog below High, and it is uploaded to the Nova shader as u_QualityLevel so the path tracer adapts its own sampling.

Sky

A two-color vertical gradient — bottom and top color — used as the environment background and, in the Nova path, as the miss radiance for rays that escape the scene. A sun direction is set independently and, when a directional light entity exists, the analytic light's direction and color override it.

Renderer2D (Wasteland/Renderer/Renderer2D.h)

Batch renderer for 2D primitives — quads, rotated quads, circles, lines, and rects, in 2D and 3D position overloads, with texture and sub-texture variants. All draws batch into a single vertex buffer per flush. An entityID parameter on several calls supports viewport picking.

Renderer2D::BeginScene(camera);
Renderer2D::DrawQuad(position, size, color);
Renderer2D::DrawRotatedQuad(pos, size, rotation, texture);
Renderer2D::EndScene();

Renderer (Wasteland/Renderer/Renderer.h)

A thin static facade over the active RendererAPI, plus the 2D scene-data struct that batches quads before submission.

NVRHI (Wasteland/src/Platform/NVRHI/)

NVIDIA's Rendering Hardware Interface provides the D3D11, D3D12, and Vulkan backends behind one device abstraction. The engine's NVRHI layer is a full parallel implementation of the resource classes — buffer, texture, vertex array, shader, framebuffer — plus:

  • NVRHIContext — device, command list, swap chain, and per-backend ImGui resource wiring (D3D11 RTVs, D3D12 descriptor heaps and command objects, Vulkan descriptor pool and render pass)
  • NVRHIRendererAPI — pipeline, compute pipeline, and binding-set caches keyed on shader and vertex-array pointers
  • RecreateResources() on every resource class, driven by the API switch

Vulkan additionally uses VulkanDispatch.cpp for volk-based function loading, defining VULKAN_HPP_DISPATCH_LOADER_DYNAMIC in exactly one translation unit.

Nova Ray Tracer

Nova is Wasteland's GPU path tracer. It is not a post-process filter over the raster path — it is a compute pipeline that traces the scene directly, and it ships as a native D3D11 and D3D12 implementation rather than going through NVRHI, so the shaders can use the native compute and resource APIs of each API.

Scene Representation

Every drawable is flattened into a RayTracingInstance structure buffer carrying its inverse and world transform, albedo, material parameters, AABB bounds, emission, LOD level, texture slot, and texture scale. A BVH is built and flattened on the CPU, uploaded as a second structured buffer, and instances are reordered to match BVH primitive order. Emissive instances are indexed into a third buffer so the path tracer can sample them as light sources.

The BVH is rebuilt only when the scene actually changes — detected by comparing against the previous frame's instance list — so a static scene pays the build cost once.

Resources

Resource Count Purpose
Structured buffers 3 Instances, BVH nodes, light indices
Images 8 Ping-pong G-buffer and history
Compute dispatch 8×8 Threads per group

Each dispatch reads immutable snapshots of its own images rather than binding a resource as both SRV and UAV — D3D11 in particular will not permit the aliasing, so the native layer copies every image to a snapshot texture at the start of each dispatch. The history image is snapshotted for temporal reprojection and updated after accumulation; the denoise result is committed back into the history slot.

Compute Passes

The shader is a single entry point switched on u_PassID:

Pass Name
0 Visibility + Velocity
1 Hybrid Trace (direct + indirect rays)
2 Temporal Indirect Accumulation (velocity-reprojected)
4 Bloom Blur Horizontal
5 Bloom Blur Vertical
6 Composite — always at full resolution
7 Bilateral Blur (denoise)
8 Upscale
9 Generate Material Maps (Sobel)
10 God Rays

The per-frame sequence is 1 → 0 → 2 → CommitHistory, then up to four bilateral-blur iterations with a doubling step size, then composite at full resolution, then bloom and god rays. Everything except composite runs at the internal trace resolution.

Progressive Refinement

When accumulation is enabled, the blend weight is max(0.02, 1 / (frame + 1)), so a static camera converges over successive frames while a moving one keeps re-sampling rather than smearing. Camera movement is detected by comparing the current and previous view-projection matrices, and a scene change resets the frame index and clears the accumulation buffers.

Anti-aliasing uses a Halton sequence: Halton(index, base) and GetCurrentJitter(frameIndex, viewportSize) produce the per-frame sub-pixel offset.

Neural Detail

The shader contains in-shader MLP blocks that add detail to three channels independently — texture, lighting, and material — each with its own strength slider. The feature is separately toggleable, and GenerateMaterialMaps (pass 9) derives normal and roughness maps from an albedo with Sobel edges, driven by normal strength and roughness bias.

Shaders

Two hand-maintained ports live in assets/shaders/: Renderer3D_NovaRenderer.glsl (~2,240 lines) and Renderer3D_NovaRenderer.hlsl (~2,340 lines). They implement identical math and pass structure. The HLSL port keeps the GLSL binding numbers as register slots so the C++ wiring maps 1:1 across both APIs, and works around the SM5 restriction on dynamic texture-array indexing with an explicit 32-way texture-slot switch.

Parity is not complete by design: the parallax occlusion mapping UV-space march is not portable to SM5, which has no dynamically-indexed texture reads. ApplyPOM keeps push, bump-normal, self-occlusion, and sun-shadow at the base UV, with the screen-space ray anchor still ray-correct.

Failure Handling

A dispatch that throws is caught in Renderer3D::Flush(), logged, and disables ray tracing for the session rather than taking down the frame — the renderer falls back to the raster path and the application keeps running.

Post-Processing

Every effect below is independently toggleable and has a matching getter/setter pair on Renderer3D, so each is adjustable at runtime from the editor or from a script. In the Nova path most are compute passes; in the raster path they are applied in the post chain.

Effect Controls
Bloom Intensity, threshold
Bilateral blur Pass count (up to 4, doubling step size)
God rays Intensity, decay, sample count, density, color
Vignette Intensity, radius, softness
Chromatic aberration Intensity
Color grading Temperature, tint, gamma
Film grain Intensity
Global fog Density, color, base height, height falloff, distance attenuation
Volumetric step scale Global multiplier on all raymarch step counts

God rays are validated per frame: the sun is projected to screen space, and the pass only runs when the sun is in front of the camera and above the horizon. God rays read a directional light's position and color when one exists, falling back to the global sun direction and a warm default.

Rendering Resources

Shader (Wasteland/Renderer/Shader.h)

Abstract shader API. Supports uniform setting for int, int arrays, float, vec2/3/4, and mat4. A ShaderLibrary manages loaded shaders by name, with Get and Exists lookups. Shaders can be created either from a file or from inline vertex/fragment source.

Ref<Shader> shader = Shader::Create("assets/shaders/PBR.glsl");
shader->Bind();
shader->SetFloat3("u_Color", color);
shader->SetMat4("u_ViewProjection", vp);

Buffer (Wasteland/Renderer/Buffer.h)

Vertex and index buffers. BufferElement describes vertex attributes (Float, Float2, Float3, Mat4, Int, and others) and reports its component count. BufferLayout owns a set of elements and auto-calculates offsets and stride.

VertexArray (Wasteland/Renderer/VertexArray.h)

VAO wrapper. Holds a list of vertex buffers plus one index buffer for draw calls.

Texture (Wasteland/Renderer/Texture.h)

Abstract texture with a Texture2D subclass, created from a file path or from dimensions, and resizable at runtime. Under NVRHI, GetNativeSRV() returns the backend-native shader resource view — a D3D11 SRV, a D3D12 resource, or a Vulkan image view — which is also what ImGui binds for rendering.

SubTexture2D (Wasteland/Renderer/SubTexture2D.h)

A rectangular region of a texture, used for sprite sheets. CreateFromCoords takes a texture, cell coordinates, cell size, and sprite size, and returns a sub-texture usable anywhere a texture is.

Framebuffer (Wasteland/Renderer/Framebuffer.h)

Render target supporting multiple color attachments and depth/stencil. Used for the editor viewport, post-processing, and the ray-trace target. It also serves the editor's picking: ReadPixel and ClearAttachment read back and reset the integer attachment that records which entity is under the cursor.

Camera (Wasteland/Renderer/Camera.h)

Abstract base camera providing view and projection matrices.

SceneCamera (Wasteland/Scene/SceneCamera.h)

Perspective and orthographic projection with configurable FOV, near/far clips, and aspect ratio. Recalculates its projection when any of those change.

EditorCamera (Wasteland/Renderer/EditorCamera.h)

Fly-style camera for the editor — pan, zoom, rotate, plus an orthographic mode for 2D editing.

OrthographicCamera (Wasteland/Renderer/OrthographicCamera.h)

Simple orthographic camera. The OrthographicCameraController beside it adds zoom and pan, and is what the Sandbox uses for 2D.

Physics

Box2D (Wasteland/vendor/Box2D)

2D physics engine. Bodies and colliders are created via Rigidbody2DComponent with BoxCollider2DComponent or CircleCollider2DComponent. The scene calls OnPhysics2DStart() / OnPhysics2DStop() to manage the world lifecycle, and the runtime fixture handles are stored inside the components.

Box3D (Wasteland/vendor/Box3D)

3D physics engine — the upstream Box3D project, not a fork. Managed by RigidBody3DComponent with box, sphere, or capsule colliders, stepped from OnPhysics3DStart/Stop and OnUpdateSimulation() with a four-velocity-iteration substep count.

Body and shape identifiers are stored as uint64_t and reconstructed with b3LoadBodyId / b3LoadShapeId at use, which keeps the Box3D types out of the component headers.

Scripting

Python 3.14 is embedded in the engine through pybind11 and exposed as a module named Wasteland, built as the WastelandPython shared library (Wasteland.pyd). Roughly 150 classes and free functions are bound, covering the full renderer, scene, ECS, and UI surface — a script can draw, spawn entities, read input, and drive post-processing settings.

Script Model

A script is a plain Python class, not a subclass of an engine type. The engine constructs it once with the owning entity, then calls one method every frame:

  1. Add a ScriptComponent to an entity in the Scene Hierarchy.
  2. Set ScriptPath to the file, e.g. assets/scripts/Player.py.
  3. Set ScriptName to the class name inside it, e.g. Player.
  4. Press Play.

ScriptEngine imports the module, instantiates ScriptName(entity), and calls OnUpdateEntity(dt) per frame where dt is a Timestep. A script whose module is already loaded is reloaded rather than re-imported, and one that fails to import is recorded in a failure set and skipped thereafter rather than throwing every frame.

import Wasteland

class Mover:
    def __init__(self, entity):
        self.entity = entity
        self.speed = 5.0

    def OnUpdateEntity(self, dt):
        if not self.entity.IsValid():
            return
        t = self.entity.GetTransform()
        t.Translation.x += self.speed * dt.GetSeconds()
        self.entity.SetTransform(t.Translation, t.Rotation, t.Scale)

Transforms from Python

Entity.GetTransform() returns a copy of the transform component, not a live reference. Mutating it has no effect until Entity.SetTransform(translation, rotation, scale) commits it. This is deliberate — it makes the read-modify-write explicit — but a script that mutates and forgets to commit will run cleanly and never move.

Rotation is in radians. The editor's inspector shows and accepts degrees and converts at the UI boundary, but TransformComponent.Rotation itself is radians, because that is what feeds glm::quat(). A first-person controller that writes degrees looks correct in the numbers and points the wrong way in the world.

Rotation is XYZ Euler order, and the scene camera builds its view as the inverse of the entity transform — so with a right-handed basis, forward is local -Z and right is local +X.

Calling the Engine from C++

The extern "C" hooks Wasteland_SetPythonEventHandler and Wasteland_GetPythonEventHandler let the engine push events into Python. Because a callback invoked from a window procedure is an unwind boundary, the dispatch path catches everything rather than letting a Python exception cross back into C.

Volumetrics & Water

Volumetric Fog (VolumetricFogComponent)

A box volume raymarched inside the fragment and path-tracing shaders. Density, Henyey-Greenstein anisotropy (forward scattering), height falloff, 3D-noise breakup with drift, and a per-volume step count control its cost. Up to MaxFogVolumes (4) render at once.

Volumetric Clouds (VolumetricCloudsComponent)

Raymarched cloud volumes with billow noise, coverage, density, high-frequency erosion for detail, wind-driven drift, silver-lining forward scatter around the sun, and self-shadowing. Up to MaxCloudVolumes (2) render at once. An ambient tint keeps the interiors from going fully black.

Both volume types are raymarched in the raster path and the Nova path, so they look consistent whichever is active. SetVolumetricStepScale() scales every volume's step count globally — the cheapest quality lever in the renderer.

Water (WaterComponent)

The surface is a six-component directional Gerstner spectrum, simulated on the CPU so that gameplay queries and the render mesh evaluate the same field and never disagree.

Spectrum

Each component carries a fixed length ratio, amplitude share, fan angle, and phase offset relative to the primary wave. Amplitudes fall off from the primary swell, and Chop scales the high-frequency detail — 0 gives a single glassy swell, 1 a full choppy sea. Each component adds a second harmonic to sharpen crests and flatten troughs, and phase speed follows deep-water dispersion (ω = √(gk)), so long swells genuinely outrun short chop instead of moving in lockstep.

Evaluation

EvaluateSurface() returns height, horizontal displacement, and an analytic normal in one pass. From it:

Method Returns
SampleHeightAt Heightfield column — what buoyancy uses, stable by construction
SampleNormalAt Analytic surface normal
CrestFactorAt 0 = trough to 1 = crest, for foam whitening
SampleFlow Current vector for river advection

Spectral LOD

The renderer passes roughly twice the mesh cell size as a minimum wavelength, and components shorter than that fade out across the Nyquist band instead of popping. Without it the water aliases into shimmer at distance; with it, distant water costs less and reads as smoother. Gameplay queries pass 0 and keep the full spectrum.

Body Types

ApplyPreset() configures a lake, river, or ocean — different color, amplitude, wavelength, flow, and foam. Rivers set FlowDirection and FlowSpeed, which advect the whole wave field downstream and drive the shore foam.

Appearance

Shallow-to-deep absorption color over a configurable depth, crest and shore foam with its own scale and band width, transparency, and specular sharpness. Up to MaxWaterSurfaces (8) render at once.

Gameplay Queries

Both queries are available on Scene and forwarded through Entity, and both are bound to Python:

  • GetWaterHeightAt(worldPos) — still level plus wave height, optionally returning the local flow vector
  • IsUnderwater(worldPos, margin) — for camera effects and swim state

The renderer skips water entirely for entities flagged !wlWater, which is how a hidden water body can still serve gameplay queries.

Profiling

A built-in instrumentor (Wasteland/Debug/Instrumentor.h) times named scopes and writes Chrome trace JSON.

WL_PROFILE_BEGIN_SESSION("Runtime", "WastelandProfile-Runtime.json");
WL_PROFILE_FUNCTION();          // times the enclosing function
WL_PROFILE_SCOPE("SceneUpdate");
WL_PROFILE_END_SESSION();

EntryPoint.h already brackets three sessions — Startup, Runtime, and Shutdown — writing WastelandProfile-Startup.json, -Runtime.json, and -Shutdown.json. The whole facility compiles out when WL_PROFILE is undefined, so it costs nothing when off.

On Windows the Python location and the Vulkan SDK path are both hard-coded in premake5.lua. A different Python install or a newer Vulkan SDK means editing those two entries and regenerating — the paths are not probed.

Step 1: Clone

git clone https://github.com/WastelandProductions/Wasteland-Engine.git
cd Wasteland-Engine

Step 2: Build NVRHI

NVRHI is built separately with CMake and consumed as a static library. Build both configurations — premake5.lua looks for nvrhi*.lib under build/%{cfg.buildcfg}/, so a missing config fails to link.

cd Wasteland/vendor/nvrhi
mkdir build && cd build
cmake .. -G "Visual Studio 17 2022" -A x64
cmake --build . --config Release
cmake --build . --config Debug

This also fetches the DirectX and Vulkan headers into build/_deps/, which the engine's include paths point at directly. docs/NVRHI_SETUP.md covers the integration in full.

Step 3: Generate Projects

# Windows — tries VS2026, falls back to VS2022, then emits a gmake2
# compilation database for VS Code
.\scripts\Win-GenProjects.bat

# Linux / macOS
./scripts/Linux-GenProjects.sh
./scripts/Mac-GenProjects.sh

Step 4: Build

# Visual Studio
msbuild Wasteland.slnx -property:Configuration=Release -property:Platform=x64
msbuild Wasteland.slnx -property:Configuration=Debug   -property:Platform=x64

# Linux & macOS
make config=release_x64

Verify with real build output — both configurations must succeed, not just the one being iterated on.

Step 5: Run

.\bin\Release-windows-x86_64\DemonCore-Editor\DemonCore-Editor.exe

The editor's post-build step copies assets/ and the Python runtime (DLL, stdlib, and extension modules) next to the executable, which is what lets the shared EntryPoint.h find assets/ without any working-directory setup.

Testing Backend Switching Headlessly

Environment variables let the editor switch renderers on a timer, for reproducing backend-switch behavior without a human at the settings combo:

WL_AUTO_SWITCH_TO=3          # 2=D3D11, 3=D3D12, 4=Vulkan
WL_AUTO_SWITCH_QUIT=120     # close after N frames
WL_AUTO_SWITCH_TO2=2        # optional second switch
WL_AUTO_SWITCH_TO2_FRAME=60

Build Configuration (premake5.lua)

The workspace defines three configurations:

  • Debug — WL_DEBUG, no optimization, symbols on. Enables WL_ENABLE_ASSERTS, so WL_ASSERT and WL_CORE_ASSERT are live and trap on failure.
  • Release — WL_RELEASE, optimized.
  • Dist — WL_DIST, optimized, no asserts.

Output lands in bin/{cfg}-{system}-{arch}/ per project, with intermediates in bin-int/.

Platform Defines

WL_PLATFORM_WINDOWS, WL_PLATFORM_LINUX, or WL_PLATFORM_MACOS select the per-OS window and input implementations. Core.h also detects these independently and rejects unsupported targets outright — x86, iOS, and Android fail the build with an explicit error rather than miscompiling.

Two Build Details Worth Knowing

  • /bigobj is mandatory on MSVC for every project that includes pybind11 headers. Without it the COFF section limit is exceeded and the compile fails. Because it is set in premake5.lua, editing a .vcxproj directly is lost on the next premake run.
  • The Vulkan SDK path is pinned. Both the NVRHI-fetched headers and the SDK provide vulkan/vulkan.hpp, so include order matters. VULKAN_HPP_DISPATCH_LOADER_DYNAMIC is defined in exactly one translation unit to keep that unambiguous.
