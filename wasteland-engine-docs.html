Overview

Wasteland Engine is a 2D/3D game engine built from scratch in C++17. It uses a layered architecture with an Application core, a Scene/Entity system built on EnTT, multiple rendering backends (OpenGL, DirectX 11/12, Vulkan via NVRHI), AI-powered ray tracing (Nova), and a full editor (DemonCore-Editor).

Core Systems

Application (Wasteland/Core/Application.h)

The Application class is the entry point for all Wasteland programs. It owns the window, runs the main loop, and manages the layer stack.

class Application {
public:
    Application(const std::string& name = "Wasteland App");
    void Run();
    void PushLayer(Layer* layer);
    void PushOverlay(Layer* layer);
    void Close();
    static Application& Get();
};

The main loop calls OnUpdate() on every layer, renders ImGui overlays, and swaps the window buffer. The static Get() singleton allows global access.

Layer (Wasteland/Core/Layer.h)

Layers are the primary unit of engine functionality. Both the editor and game systems are implemented as layers.

class Layer {
public:
    virtual void OnAttach() {}
    virtual void OnDetach() {}
    virtual void OnUpdate(Timestep ts) {}
    virtual void OnImGuiRender() {}
    virtual void OnEvent(Event& event) {}
};

The EditorLayer (in DemonCore-Editor) and Sandbox2D are the two main layer implementations.

Timestep (Wasteland/Core/Timestep.h)

A simple wrapper around a float representing seconds since last frame. Provides GetSeconds() and GetMilliseconds().

Window (Wasteland/Core/Window.h)

Abstracts platform-specific window creation (GLFW-backed). Handles input callbacks, vsync, and resize events.

Events (Wasteland/Events/Event.h)

Blocking event system. Event types include:

  • WindowClose, WindowResize, WindowFocus
  • KeyPressed, KeyReleased, KeyTyped
  • MouseButtonPressed, MouseButtonReleased, MouseMoved, MouseScrolled

Events are dispatched immediately via EventDispatcher which routes to handler functions.

Log (Wasteland/Core/Log.h)

Static logger using spdlog. WL_CORE_INFO(), WL_CORE_ERROR(), etc. for engine-side logging.

Scene System

Scene (Wasteland/Scene/Scene.h)

The Scene owns an entt::registry and manages entity lifetime. It handles three update paths:

  • OnUpdateEditor() — Editor preview with EditorCamera
  • OnUpdateRuntime() — Play mode
  • OnUpdateSimulation() — Physics-only simulation

The scene also manages volumetric volumes (fog, clouds), water surfaces, and light submission to the renderer.

Entity (Wasteland/Scene/Entity.h)

An Entity is a lightweight handle wrapping an entt::entity and its parent Scene. It provides a templated component API:

Entity entity = scene.CreateEntity("Player");
entity.AddComponent<TransformComponent>();
auto& transform = entity.GetComponent<TransformComponent>();
bool has = entity.HasComponent<SpriteRendererComponent>();

Rendering

Renderer (Wasteland/Renderer/Renderer.h)

The static Renderer class initializes the active API and provides BeginScene()/EndScene()/Submit() for the 2D pipeline.

Renderer2D (Wasteland/Renderer/Renderer2D.h)

Batch-renderer for 2D primitives. Draws quads, rotated quads, circles, and lines. All 2D draws are batched into a single vertex buffer per flush.

Renderer2D::BeginScene(camera);
Renderer2D::DrawQuad(position, size, color);
Renderer2D::DrawRotatedQuad(pos, size, rotation, texture);
Renderer2D::EndScene();

Renderer3D (Wasteland/Renderer/Renderer3D.h)

Full 3D renderer with PBR materials, ray tracing support, volumetric effects, and water rendering. Key features:

  • QualityPreset: Low, Medium, High, Ultra
  • Dynamic resolution scaling (0.5–1.0) with target FPS
  • Ray tracing accumulation for progressive refinement
  • Render scale adjustable at runtime

NVRHI (Wasteland/vendor/nvrhi)

NVIDIA Rendering Hardware Interface provides DirectX 11, DirectX 12, and Vulkan backends. The engine can switch APIs at runtime — all GPU resources are rebuilt via RecreateResources().

Nova Renderer

Nova is the AI-powered rendering pipeline. It sits on top of Renderer3D and provides:

  • AI denoising for ray-traced frames
  • AI upscaling (DLSS-like) for performance
  • Intelligent sample distribution to reduce noise
  • Volumetric fog and cloud raymarching
  • Gerstner wave simulation for water

Rendering Resources

Shader (Wasteland/Renderer/Shader.h)

Abstract shader API. Supports uniform setting for int, float, vec2/3/4, and mat4. A ShaderLibrary manages loaded shaders.

Ref<Shader> shader = Shader::Create("assets/shaders/PBR.glsl");
shader->Bind();
shader->SetFloat3("u_Color", color);
shader->SetMat4("u_ViewProjection", vp);

Buffer (Wasteland/Renderer/Buffer.h)

Vertex and index buffers. BufferElement describes vertex attributes (Float, Float2, Float3, Mat4, Int, etc.). The layout is auto-calculated with offsets and strides.

VertexArray (Wasteland/Renderer/VertexArray.h)

VAO wrapper. Binds vertex buffers and an index buffer together for draw calls.

Texture (Wasteland/Renderer/Texture.h)

Abstract texture with Texture2D subclass. Created from file path or dimensions. Under NVRHI, GetNativeSRV() returns a D3D shader resource view for ImGui rendering.

Framebuffer (Wasteland/Renderer/Framebuffer.h)

Render target supporting multiple color attachments and depth/stencil. Used for the editor viewport, post-processing, and ray tracing targets. Format options: RGBA8, RED_INTEGER (for picking), DEPTH24STENCIL8.

Camera (Wasteland/Renderer/Camera.h)

Abstract base camera. Provides view and projection matrices.

SceneCamera (Wasteland/Scene/SceneCamera.h)

Supports perspective and orthographic projection. Configurable FOV, near/far clips, and aspect ratio. Automatically recalculates projection on change.

EditorCamera (Wasteland/Renderer/EditorCamera.h)

Fly-style camera for the editor. Pan, zoom, rotate. Orthographic mode for 2D editing.

OrthographicCameraController (Wasteland/Renderer/OrthographicCameraController.h)

2D camera with zoom and pan. Used in the editor viewport for 2D scenes.

Physics

Box2D (Wasteland/vendor/Box2D)

2D physics engine. Bodies and colliders are created via Rigidbody2DComponent and BoxCollider2DComponent. The scene calls OnPhysics2DStart()/OnPhysics2DStop() to manage the physics world lifecycle.

Box3D (Wasteland/vendor/Box3D)

3D physics engine (fork of Box3D). Managed by Rigidbody3DComponent and BoxCollider3DComponent. Provides 3D collision detection and rigid body dynamics.

Scripting

Python Integration (Wasteland/vendor/pybind11)

Python 3.14+ is embedded via pybind11. Game scripts inherit from ScriptableEntity and can override OnCreate(), OnUpdate(), and OnDestroy().

class PlayerController(script.ScriptableEntity):
    def OnCreate(self):
        print("Player spawned")
    def OnUpdate(self, ts):
        transform = self.GetComponent(TransformComponent)
        transform.Translation.x += 1.0 * ts

ScriptableEntity (Wasteland/Scene/ScriptableEntity.h)

Base class for all script components. Wraps an Entity and provides component access methods that delegate to the entity.

ScriptComponent (Components.h)

Stores a ScriptableEntity* instance. Created when a Python script file is attached to an entity in the editor.

DemonCore Editor

EditorLayer (DemonCore-Editor/src/EditorLayer.h)

The main editor layer. Owns the active scene, viewport framebuffer, gizmo state, and all editor panels. Handles scene serialization (YAML), play/stop/simulation modes, and toolbar rendering.

Volumetrics & Water

Volumetric Fog (VolumetricFogComponent)

Screen-space raymarched fog. Submitted via SubmitVolumetricVolumes() between BeginScene/EndScene. Supports density, scattering, and absorption parameters.

Volumetric Clouds (VolumetricCloudsComponent)

Raymarched volumetric clouds with noise-based density. Rendered as a post-process pass with lighting integration.

Water System (WaterComponent)

Gerstner wave simulation for water surfaces. Features:

  • Configurable wave parameters (amplitude, length, speed, choppiness)
  • Phase wrapping (mod 2π) to prevent floating-point drift
  • Distance LOD to reduce aliasing at distance
  • Buoyancy queries: GetWaterHeightAt() returns still level + wave height
  • Flow vectors for river currents
  • Underwater detection: IsUnderwater()

Building

Prerequisites

Component Windows Linux macOS
Compiler Visual Studio 2022+ GCC/Clang Xcode CLI Tools
Python 3.14+ 3.14+ 3.14+
CMake 3.16+ (for NVRHI) 3.16+ 3.16+
Vulkan SDK 1.3.296.0 1.3.296.0 —

Step 1: Clone

git clone https://github.com/Ashen-Wastes-Studios/Wasteland-Engine.git
cd Wasteland-Engine

Step 2: Generate Projects

# Windows
.\scripts\Win-GenProjects.bat

# Linux
./scripts/Linux-GenProjects.sh

# macOS
./scripts/Mac-GenProjects.sh

Step 3: Build NVRHI

cd Wasteland\vendor\nvrhi
mkdir build && cd build
cmake .. -G "Visual Studio 17 2022" -A x64
cmake --build . --config Release
cmake --build . --config Debug

Step 4: Build Engine

# Windows
msbuild Wasteland.slnx -property:Configuration=Release -property:Platform=x64

# Linux & macOS
make config=release_x64

Step 5: Run

.\bin\Release-windows-x86_64\DemonCore-Editor\DemonCore-Editor.exe

Build Configuration (premake5.lua)

The workspace defines three configurations:

  • Debug — No optimizations, debug symbols, validation layers enabled
  • Release — Optimized, some validation
  • Dist — Fully optimized, no validation, distribution build

Output directory: bin/{cfg}-{system}-{arch}/

Dependencies included:

GLFW, Glad, ImGui, glm, stb_image, entt,
yaml-cpp, ImGuizmo, Box2D, Box3D,
pybind11, NVRHI, VulkanSDK
